# 620 — Dependencies go unused and out of date unnoticed

**Status:** open
**Type:** refactoring
**Priority:** medium
**Area:** Maintenance
**Summary:** Cargo 1.100 warns of four dependencies two crates declare and do not use - three of `caelumora-rest-client`, the domain of `caelumora-subagents` built without features -, which no check of the workspace refuses, and nothing keeps the dependencies of the Rust workspace and of the web UI up to date, so they fall behind their newest versions unnoticed.

## The problem

### Unused dependencies

Since Cargo 1.100 (Fedora's `cargo 1.100.0`, 2026-11-05) every build warns of dependencies a crate
declares and does not use (`cargo::unused_dependencies`, `warn` by default). In the workspace four
are reported, of two crates:

- `caelumora-rest-client/Cargo.toml`: `serde`, `serde_json`, `anyhow` - in every build.
- `caelumora-subagents/Cargo.toml`: `caelumora-domain` - only built without features
  (`--no-default-features`), as the pre-commit hook builds the crates that stand on both levels
  (issue 516): that build holds nothing of the crate, every module of it needs `api`, `kernel` or
  `library`, but the domain is no optional dependency. The other crates of both levels
  (`caelumora-artifacts`, `caelumora-memory`, `caelumora-notes`, `caelumora-skills`) use it there
  and warn of nothing.

`caelumora-rest-client` is empty: its `src/lib.rs` holds nothing, no crate depends on it, and
ARCHITECTURE.md, CRATES.md and README.md call it "reserved for a client of the REST interface;
empty so far".

The warning is a warning of Cargo, not a lint of rustc: `cargo clippy -- -D warnings`, which the
pre-commit hook runs, does not refuse it, and `[workspace.lints]` holds no rule for it. A
dependency left unused by a later change is warned of in every build and refused nowhere.

### Dependencies out of date

Nothing brings the dependencies up to date, neither by a rule nor by a tool:

- **Rust:** the workspace's dependencies are versioned in `[workspace.dependencies]` of the root
  `Cargo.toml` and locked in `Cargo.lock`. `cargo update --dry-run --verbose` on 2026-11-27 would
  update 101 locked packages within their ranges (`tokio` 1.53.1 → 1.54.1, `hyper` 1.11.1 →
  1.13.0, `uuid` 1.26.1 → 1.29.3, …), and finds seven direct dependencies a major version behind:
  `minijinja` 2.24 → 3.1, `jsonwebtoken` 11.1 → 12.0, `rustyline` 18 → 19, `serde-saphyr` 1.3 →
  2.2, `base64` 0.22 → 0.23, `htmd` 0.5 → 0.6, `sse-stream` 0.2 → 0.3.
- **Node:** the web UI (`caelumora-web-ui/package.json`, `package-lock.json`). `npm outdated` on
  2026-11-27 lists 16 of 26 packages behind, among them:
  - within their ranges: `lucide-react` 1.48.0 → 1.82.0, `eslint` 10.11.0 → 10.15.0, `vite`
    8.3.1 → 8.4.0, `typescript-eslint` 8.70.1 → 8.74.0, `react`/`react-dom` 19.3.0 → 19.3.1, and
    patch releases of `tailwindcss`, `postcss` and others;
  - new major versions: `typescript` 6.0.3 → 7.0.2 (`~6.0.2` in `package.json`), `@types/node`
    24 → 26.

## Why it matters

- A warning in every build that nobody acts on teaches to overlook warnings - the next one too.
- A declared but unused dependency is built, audited and updated for nothing, and says something
  false about what a crate depends on (CRATES.md draws the graph from the manifests).
- Dependencies far behind are updated at once, many major versions together, when a security fix
  forces it - the most expensive moment to do it.

## Considerations

### Unused dependencies

- **The empty crate**: remove its three dependencies, or remove the crate itself until a client of
  the REST interface is built. AGENTS.md: "Nothing without a user" - a crate reserved and empty is
  a crate without a user; the name stays free for when it is built. Removing it touches the
  workspace members, CRATES.md (graph, generated by `scripts/crate-graph.sh`), ARCHITECTURE.md and
  README.md.
- **The domain of `caelumora-subagents`**: an optional dependency, part of `api` - whatever of the
  crate is built uses it -; or something of the crate without features that uses it, if a client
  should read anything of sub-agents, as it reads the others' names and texts.
- **Keeping it refused**: the warning becomes an error, so that the next one cannot be
  overlooked: by `[workspace.lints]` if Cargo's lints are configurable there (`[lints.cargo]`), or
  by the pre-commit hook failing on a build that warns of an unused dependency. To check which way
  Cargo 1.100 offers.

Recommended: remove the empty crate, make the domain of `caelumora-subagents` part of `api`, and
refuse the warning by the lint table if Cargo allows it, else by the hook - which then has to
refuse it in the builds without features too.

### Bringing the dependencies up to date

- **Once, now**: every Rust and Node dependency to its newest version, semver-compatible and major,
  each major version a step of its own with what it changes in the code; tests, clippy, the web
  UI's build and lint, and the web UI checked in a browser.
- **Regularly after that**: a rule in a document (CODING-GUIDELINES.md, or a document on
  maintenance) to update at a fixed occasion - before a release, or monthly -, possibly with a tool
  that reports what is behind (`cargo outdated` or `cargo update --dry-run --verbose`, `npm
  outdated`), run by hand or by a script in `scripts/`. A bot opening pull requests (Dependabot,
  Renovate) needs the GitHub mirror and fits the workflow of this repository less, where the
  maintainer reviews each step.

Open: TypeScript 7 (the compiler rewritten in Go) and `@types/node` 26 - whether the web UI's tool
chain (`typescript-eslint`, `vite`, `vitest`) supports them yet; else they wait, with the reason
recorded here.

## Done when

- No build of the workspace warns of an unused dependency, and a new one is refused.
- Every Rust and Node dependency is at its newest version, or the reason why not is recorded here.
- Tests, `cargo clippy --workspace --all-targets`, the web UI's build, lint and tests pass, and the
  web UI is checked in a browser.
- How dependencies are kept up to date from now on is decided and written down.
